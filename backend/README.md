# Zoom Workplace Clone — Backend

FastAPI + SQLAlchemy (SQLite) API for the Zoom Workplace clone. Real
account auth (JWT + bcrypt) — every request that isn't `/api/auth/register`
or `/api/auth/login` requires a valid bearer token.

## Setup

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

Create `backend/.env` with a secret key (`auth.py` raises `RuntimeError` at
import time if this isn't set):

```
SECRET_KEY=<any long random string>
```

Generate one quickly with `python -c "import secrets; print(secrets.token_hex(32))"`.

```bash
python -m app.seed             # creates app.db and populates 5 demo users + 8 demo meetings
uvicorn app.main:app --reload --port 8000
```

API docs (Swagger UI): http://localhost:8000/docs

```
│   ├── schemas.py          Pydantic request/response models
│   ├── crud.py             Query functions + meeting ID / passcode / invite-link generation

│   ├── seed.py              Wipes + repopulates app.db with demo data
│   └── routers/
│       ├── auth.py          POST /register, /login, GET /me
│       ├── users.py         GET /{user_id}
│       ├── meetings.py      Meeting CRUD, join/leave, messages, recording, mute-all
│       └── participants.py  PATCH/DELETE on a single participant
├── requirements.txt
└── .env                     SECRET_KEY (gitignored — not committed)
```

## Auth

- `POST /api/auth/register` `{ name, email, password }` → `{ access_token, token_type, user }`
- `POST /api/auth/login` `{ email, password }` → same shape
- `GET /api/auth/me` → current user (requires `Authorization: Bearer <token>`)
- Tokens are HS256 JWTs, 24-hour expiry, `sub` claim = user id.
- Every other route depends on `get_current_user`; a missing/invalid/expired
  token returns `401`.

## API reference

All meeting/participant routes are prefixed `/api/meetings` and
`/api/participants` respectively and require auth.

| Method | Path | Notes |
|---|---|---|
| GET | `/api/meetings/today` \| `/upcoming` \| `/recent` | Scoped to meetings the current user hosts or has joined |
| GET | `/api/meetings/by-date?date=YYYY-MM-DD` | |
| POST | `/api/meetings/instant` | `{ title? }` — creates + starts immediately |
| POST | `/api/meetings/schedule` | `{ title, description?, start_time, duration_minutes }` (30/60/90 only) |
| GET | `/api/meetings/{meeting_id}` | Full detail incl. participants; passcode is stripped unless you're the host |
| PATCH | `/api/meetings/{meeting_id}` | Host-only — title/description |
| DELETE | `/api/meetings/{meeting_id}` | Host-only |
| POST | `/api/meetings/{meeting_id}/end` | Host-only |
| POST | `/api/meetings/{meeting_id}/recording/start` \| `/stop` | Host-only, toggles `is_recording` |
| POST | `/api/meetings/{meeting_id}/join` | `{ display_name, passcode, is_muted?, is_video_on? }` — 401 on wrong passcode, 400 if meeting ended |
| POST | `/api/meetings/{meeting_id}/leave` | `{ participant_id }` |
| GET | `/api/meetings/{meeting_id}/participants` | |
| GET/POST | `/api/meetings/{meeting_id}/messages` | POST requires the caller to already be a participant |
| POST | `/api/meetings/{meeting_id}/mute-all` | Host-only |
| PATCH | `/api/participants/{id}` | Self-only — mute, video, active-speaker, hand-raise, reaction |
| DELETE | `/api/participants/{id}` | Host-only, can't remove the host |
| GET | `/api/users/{user_id}` | |

## Data model

- **User** — `name`, `email` (unique), `hashed_password`, `avatar_url`, `is_online`
- **Meeting** — `meeting_id` (unique, `"XXX XXXX XXXX"` format), `passcode`,
  `host_id`, `title`, `description`, `meeting_type` (`instant`/`scheduled`),
  `start_time`/`end_time`/`duration_minutes`, `status`
  (`scheduled`/`active`/`ended`), `invite_link`, `is_recording`
- **Participant** — belongs to a meeting + optionally a user (guests can
  join with `user_id = null`), `is_host`, `is_muted`, `is_video_on`,
  `is_active_speaker`, `is_hand_raised`, `reaction` + `reaction_at`,
  `joined_at`/`left_at`
- **Message** — `meeting_id`, `participant_id`, `text`, `created_at`

## Notes

- **Meeting IDs** are generated by `crud.generate_meeting_id` — a random
  10-digit number formatted `"XXX XXXX XXXX"`, checked for DB uniqueness.
  `crud.normalize_meeting_id` accepts the ID with or without spaces (or
  `%20`) so lookups work regardless of how the frontend formats it.
- **Invite links** (`crud.build_invite_link`) are
  `https://app.local/join/{id}?pwd={passcode}` — update the host in that
  function once you know your deployed frontend's real domain.
- CORS is wide open (`allow_origins=["*"]`) in `main.py` — fine since auth
  uses a bearer token header, not cookies.
- `app.db` (SQLite) is created automatically on first run via
  `Base.metadata.create_all` in `main.py`; `python -m app.seed` additionally
  **drops and recreates every table** before populating demo data — only
  run it when you want a clean slate, not against a database with real
  user signups you want to keep.

## Deployment (Render)

1. Push this repo to GitHub.
2. Render → New → Web Service → connect the repo, set **Root Directory** to `backend`.
3. Build command: `pip install -r requirements.txt`
4. Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
5. Environment → add `SECRET_KEY` (a long random string).
6. Deploy, then open the service's **Shell** tab once and run `python -m app.seed` if you want the demo data live (optional — real signups work without it).
7. Note the service's public URL (`https://<name>.onrender.com`) — the frontend needs it as `NEXT_PUBLIC_API_URL`.
